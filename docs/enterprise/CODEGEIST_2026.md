# Codegeist 2026 submission gate

Official rules: https://codegeist2026.devpost.com/rules
Submission deadline: 2026-12-22 12:00 PST (23:00 Baghdad). Target internal submission: December 19.
Proposed category: Apps for Business Teams (financial investigation and evidence handoff). Existing FraudShield code is eligible in principle only if rebuilt or updated on Forge during the contest period and all other rules are met. Do not claim eligibility is approved.

## Mandatory acceptance
- [ ] Register entrant on Devpost and obtain Atlassian Cloud developer site.
- [ ] Register actual Forge app and configure HTTPS remote, separate synthetic tenant and identity bindings.
- [ ] Deploy, install, upgrade and uninstall on a clean authorized Jira/Confluence developer site; test mapped and unmapped accounts.
- [ ] Provide working judge installation link and repeatable English configuration instructions; verify judge onboarding does not require sharing credentials or production data.
- [ ] Record English public YouTube demo under five minutes showing actual end-to-end behavior.
- [ ] Complete Devpost description, category, technology explanation and applicable prize requirements before cutoff.
- [ ] Freeze exact tested SHA, collect CI and live installation evidence, check open-source and third-party rights.
- [ ] Maintain judge availability throughout judging Jan 5–Feb 3, 2027.

## Equal-weight criteria
Implementation: demonstrate real Jira issue receipt linkage, remote verification and persistence, not a hardcoded screen.
Design: clear receipt state, recovery and actionable errors.
Impact: evidence handoff for finance investigators; measure time saved versus manual process, do not invent results.
Innovation: verifiable evidence handoff with tenant-scoped original bytes and audit trail; compare alternatives honestly.
Presentation: English walkthrough from transaction to verification, including unauthorized-access behavior.

No paid services or optional Rovo/MCP prize work without a verified budget and core readiness. Actual live Forge/Auth0 installation and judge link are unverified. The current remote supports one provisioned organization and installation per deployment; judge onboarding must be resolved before submission.
