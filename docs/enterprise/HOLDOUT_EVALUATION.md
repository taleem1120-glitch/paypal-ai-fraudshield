# Offline holdout evaluation

Run `python -m enterprise_core.holdout_evaluation DATA.jsonl --cutoff 2026-01-01T00:00:00Z --provenance authorized_holdout` only on authorized de-identified data. Each JSON line requires a unique UUID `id`, timezone-aware `observed_at` strictly after the predetermined cutoff, boolean confirmed fraud `label`, and `transaction` matching TransactionInput. The input must contain no personal data. Use synthetic provenance for fixtures. Provenance is caller-attested, not verified by software; ensure labels are independently adjudicated, features were available at decision time, and the holdout was not used for tuning. The fixed policy flags high-risk cases; the amount-only baseline flags amounts above USD 1000 on identical scored coverage. Results include confusion counts, coverage, precision, scored and all-case recall, scored FPR and review rate by currency; undefined ratios are null. No raw rows are exported. The dataset digest supports reproducibility but is not proof of provenance. This is an evaluation harness, not a measured performance claim or a change to production scoring. Unsupported currencies and missing indicators abstain; abstentions require human review. No real holdout data is bundled.

Review rate counts flagged cases only; review_rate_including_abstentions counts flagged and unscored cases as a conservative manual review workload estimate. Neither is a measured staffing cost.
